## Agent 번호 및 보고서 버전

`report_finding` 선택적 매개변수를 추가했습니다.，배열 순서는 초기 증거 순서입니다.：

```json
{
  "traffic_refs": [
    {"traffic_id": "실제 트래픽ID", "role": "baseline", "note": "일반계정요청"},
    {"traffic_id": "또 다른 실제 트래픽ID", "role": "proof", "note": "복제요청"}
  ]
}
```

은(는) 다음 용도로 사용됩니다. `baseline`（일반제어）、`proof`（취약점 증명）、`verification`（보충검증）、`supporting`（뒷받침하는 증거，기본값）。먼저 사용해 보세요 `traffic_search` / `traffic_get` 실제 기록을 확인하세요；도메인 이름과 시간은 후보자 심사에만 사용됩니다.，작업 소유권이 추정되지 않습니다.。

프롬프트 단어 참조 [CyberStrikeAI 의 취약점 보고 도구 가이드](https://github.com/RuoJi6/CyberStrikeAI/blob/54d56774b8bd285817d16d48b70a4a5e6e0963f7/internal/app/vulnerability_tools.go)，이 프로젝트의 선택적 바인딩 규칙과 결합됩니다.，패키지 이유 없음을 도입하지 않은 경우 확인 필요。추측 금지 ID，보충 패킷에 대해서만 탐지를 반복해서는 안 됩니다.。

반환된 첫 번째 줄은 여전히 `finding recorded: <노드 탐색 ID>`；그러면 JSON 독립적인 취약점 기록 제공 `finding_id`、노드 탐색 `finding_node_id` 및 바인딩 요약。

- `get_finding_traffic(finding_id)` 사용**독립적인 취약점 기록 ID**，순서가 지정된 목록을 반환하고 `version`；합격 `binding_id`、`side=request|response`、`offset`、`length` 세그먼트 단위로 읽을 수 있습니다.，단락당 최대 8192 바이트。

- 이전 보고서가 미전송 버전을 호출할 때，기존 교통 증거를 포함한다고 주장하지 않습니다.。바인딩、설명、용도 또는 주문 변경 후，업데이트할 보고서 프롬프트가 있습니다.。

## API

기본경로：`/api/exploration/findings/{finding_id}/traffic`，독립적인 취약점 사용 ID。인증을 계속 사용하세요；`context_task` 작업 가시성 및 상속을 읽기 전용으로 확인。

| 방법 / 상대 경로 | 요청 / 복귀 |
| --- | --- |
| `GET` | 순서대로 요약、증거 버전、보고서 채택 버전 |
| `POST` | `{"traffic_refs":[...]}` 전체 배치 추가 |
| `PATCH /{binding_id}` | `{"version":1,"role":"proof","note":"설명"}` |
| `DELETE /{binding_id}` | `{"version":1}` |
| `PUT /order` | `{"version":1,"binding_ids":["2","1"]}`，전체 목록이어야 합니다. |
| `GET /{binding_id}` | 스냅샷 메타데이터 및 경계 텍스트 미리보기 |
| `GET /{binding_id}/body` | `side`、`offset`、`length`；`download=1` 전체 원본 바이트 다운로드 |

버전/정렬된 컬렉션 충돌、아카이브에 글을 쓰고 돌아왔다. `409`；상속받은 글 `403`；존재하지 않거나 취약점이 아닌 바인딩 `404`；교통/첨부파일 읽기 및 확인에 실패하고 명확한 오류가 반환되었습니다.。
